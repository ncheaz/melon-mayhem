THE CATAPULT SWING WAS FIGHTING ITSELF (2026-09-10)

  • Two bugs in one rig. The 3D drew the arm with rotation.z (three.js: +ve = tip UP) but the melon's release point was computed as if the same angle were canvas-space (+ve = tip DOWN). So the arm was painted above the axle while the melon spawned from a point below it — the melon never left the scoop it was drawn in.
  • And the release was a teleport. The angle jumped from the cocked pose to the fired pose in a single frame (a 215° snap), then slowly drooped back. There was no swing to watch.
  • Fix: one convention, three consumers. G.PULT_ARM now holds the key angles in a single world convention (0 = arm horizontal, +ve = tip raised forward), shared by the 2D sprite, the 3D rig and the melon release point. Canvas rotate() is inverted, so the 2D painter is handed -a; that inversion is exactly what had been silently wrong.
  • The cycle, measured: ready +54° (scoop up-forward, melon loaded high) → winds to −143° (back and LOW) → release whips through to +74° (forward and HIGH) in 0.07s, monotonic with no snap → eases back to ready over 0.5s. Probe trace: −143° → −5° → +47° → +74° frame by frame.
  • Both paths match: the 2D arm is painted behind the pot when swung back (no impalement read), and the 2D and 3D release points are both derived from the same launch angle.

FEEL CHANGES (2026-09-10)

  • Hits stagger zombies. A hit stops the zombie dead, resets its move timer and adds 1 extra second of standing before it shambles on — so it loses the progress it had made toward the next square. The bonus is capped at 2s so a burst of hits can't pin a zombie to the spot, and it snaps to the nearest grid square so the 4×10 grid contract holds.
